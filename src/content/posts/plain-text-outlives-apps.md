## The ten-year test

Before you write a note in any app, ask one question: will I be able to
read this in ten years? Not "will the app still exist" — will the *file*
still open, in *something*, on whatever computer I own then?

If the answer is "only if the app is still running," you don't own the
note. The app does.

## Why plain text wins

Plain text has no version, no vendor, no expiry. A `.txt` file from 1995
opens today. A `.md` file will open in 2035. There is no format committee
that can deprecate it, no company that can shut it down, no license that
can expire.

Every other format is a bet on someone else's roadmap.

## The workflow

1. Write in markdown.
2. Store the files somewhere you control — a folder, a git repo, a
   drive you can export.
3. Back them up like you'd back up photos.

That's it. The tool can change every year. The words don't have to.

## What we're building toward

Quill is a writing surface, not a vault. We want the editor to be the
best in class, and we want the *output* to be boringly, reliably
portable. If we ever stop being the best editor for you, your archive
should already be in a shape that lets you walk away in an afternoon.
